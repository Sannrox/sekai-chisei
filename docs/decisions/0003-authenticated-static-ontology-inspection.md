# ADR 0003: Inspect ontology through authenticated static artifacts

- Status: proposed
- Date: 2026-07-22
- Owners: @Sannrox
- Discussion: https://github.com/Sannrox/sekai-chisei/issues/150#issuecomment-5049312245
- Supersedes: none
- Superseded by: none

## Context

Operators need to browse ontology classes and relations and inspect one
asserted/derived provenance trace. The first UI slice must not create an
unauthenticated read path, expose hidden nodes through counts or explanations,
or commit the project to a frontend service before its interaction needs are
known. Issue [#150](https://github.com/Sannrox/sekai-chisei/issues/150)
compared an authenticated static export with an authenticated loopback viewer.

## Decision

The first inspection UI is a self-contained HTML artifact generated by
`sekaictl ontology inspect`. Generation uses the existing authenticated gRPC
client and only serializes definitions and trace data returned to that caller.
The artifact is read-only, has no remote assets or browser persistence, and
declares its authorization context, source, snapshot time, expiry, and ontology
revisions. The complete authorized class/relation lists receive a stable local
snapshot revision, while the trace retains the service-provided entailment
revision.

Search, counts, and detail expansion operate only over the authorized snapshot.
The artifact does not query SQLite or the API after generation and is never a
source of truth. It is disclosed data: revocation is not retroactive, so a
bounded expiry and operator file handling are part of the contract.

## Alternatives considered

An authenticated loopback HTTP viewer could recheck authorization on every
interaction and reflect revocation immediately. It would also introduce a new
browser session boundary, including CSRF, origin and DNS-rebinding policy,
binding rules, cache separation, lifecycle management, and another deployable
service. Those costs are not justified by the first slice.

Extending raw CLI or JSON reports alone would avoid HTML risk but would not
provide the requested browse, filter, and expandable trace experience.

## Consequences

The control plane retains one live authorization boundary and adds no daemon,
port, database reader, or frontend dependency. Operators can inspect a portable
snapshot with an ordinary browser.

Exports may outlive a grant until their declared expiry and can be copied.
Callers must treat them like any other disclosed report, use a suitable
authorization-context label, and delete them according to local handling and
retention policy. A future live viewer requires a separate trust-boundary
decision and does not inherit approval from this ADR.

## Validation

Deterministic tests verify bounded TTL parsing, active/expired status, safe JSON
embedding, text-only rendering, absence of browser persistence, and omission of
denial counters and credentials. Existing Sekai service authorization tests
remain the evidence that list and retrieval responses are filtered before the
exporter receives them. The decision should be revisited only when operators
need live mutation, server-side search, or authorization-aware refresh.
